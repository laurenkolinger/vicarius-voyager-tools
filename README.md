# Atlas control panel

Last updated: 2026-09-27 (LO)

The Atlas control panel is the one window that holds the restricted settings and tools of the atlas, the Voyager runs, the manual edit and the desktop. It is the module `voyager_tools` (section 7 of `/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-09-03-voyager-program-design.md`, and program C of the manual edit chain, `/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-09-26-chain-c-atlas-control-panel-design.md`); only the name people see changed, so the slug `voyager_tools`, the address `/voyager-tools`, the actor prefix `voyager_tools:` and the browser keys stay (`docs/adr/0002-atlas-control-panel-display-name-only.md`). It is a native blueprint the VICARIUS desktop mounts at `/voyager-tools` on port 5090 (`/mnt/rip/vicarius_drive/vicarius_ui_os/voyager_tools_views.py`), opened from the DEV folder item ATLAS CONTROL PANEL, which only appears in admin mode, and from the link in the atlas row view. Every route answers 401 outside admin mode and 423 while the module lock `voyager_tools` is on.

## The settings panes

The settings panes (`static/vt_settings.js`, `templates/voyager_tools/panes_settings.html`) read and write the desktop's own routes under `/api/settings` (`/mnt/rip/vicarius_drive/vicarius_ui_os/settings_views.py`), one write path per settings file, each change appended to the settings history `/mnt/rip/vicarius_drive/vicarius/_METADATA/settings_history.csv` with who, when, the old and new value and the reason. A pane shows its fields as rows, the time and initials of the last save, a drift line with **Record as found** when the file changed outside the write path, one Reason row, and one save button that is enabled only when a value differs; a save posts only the changed settings with the save time the pane read, so two people saving the same file see the second refused.

- **Manual edit settings**: the scale error limits in mm and percent, the marker spread limit, markers per chunk, the edit bench default and open and close logging, in `/mnt/rip/vicarius_drive/vicarius/_METADATA/3d/manual_edit/settings.json`. The manual edit module no longer carries a settings form; its settings GET stays for its own code.
- **Shelf copy**: Archive the Shelf copy (rename the Shelf folder to `<folder>_voy1_archive` before the upload) or Overwrite the Shelf copy (replace it, deleting the files the edit removed). Either change asks for a reason and a confirmation naming the consequence; Overwrite can be chosen once the driver's `return_to_shelf` carries `mirror_delete`.
- **Voyager runs**: the Voyager 1 run switch and the Workbench removal default in `/mnt/rip/vicarius_drive/vicarius_ui_os/config/voyager.json` (the Voyager 2 rows appear once that file holds its `voyager2` block); a run switch change asks for a reason and a confirmation.
- **Space floors**: the Workbench floor, the Shelf floor and the headroom factor in the driver's `config/nas.yaml`, each change confirmed with a reason; the pane says whether the running driver has read the saved values.
- **GPU ladder**: the right-of-way tiers from `/mnt/rip/vicarius_drive/vicarius/_METADATA/gpu_ladder.yaml` and the claims holding the cards now, read only.
- **Module locks**, **Module details** and **Appearance**: read only for now, each opening the place that changes it (a module window's title-bar padlock, the Module Menu, the desktop's Admin window), until their files gain a settings history write path.
- **Settings history**: every line newest first, filtered by store, setting and day, with Copy as CSV and a line for each unreadable line and each Synology conflict copy.

On the standalone host, which serves no `/api/settings` routes, a settings pane says the settings are served by the desktop.

## Review queue, Uploads and Timelines

- **Review queue** (`static/vt_review.js`, `voyagertools/review_queue.py`, `voyagertools/manual_edit_views.py`): every transect in admin review across the unfinished manual edit projects (a transect whose atlas status reads review, with its edit round, editor, confirmation time and failed and warned checks), every start over that stopped with the stage and the reason, every transect marked for upload that no upload set holds yet, and one line per atlas row in review that no project holds. Review on a row opens that transect's review content under the list, signed with the panel's initials. The review content is one fragment (`GET /voyager-tools/fragment?tool=review&job=&psx=`, `templates/voyager_tools/review.html`, mounted by `VoyagerTools.mountReview`) that the atlas's admin review sidecar mounts too: the manual edit module's review record of the transect (checks with the editor's explanations and the limits they were judged under, scale and alignment per chunk, time in Metashape by round with the opens that have no recorded close, the admin's inspection time, time in editing and in review from the atlas status changes, the certification, the notes of the current round with earlier rounds collapsed, the bench copy), Open in Metashape, and the decision: an admin report, Mark for upload (with Start the upload now), Send back with instructions or Start over (after a confirmation naming the bench folder that moves aside and the Shelf folder the fresh copy comes from), then Record decision; Resume start over for a stopped start over, which posts the report and instructions of the first Start over again; Back to admin review for a transect marked for upload until its upload starts. The record is read again before a decision posts, so a transect that changed meanwhile posts nothing. Every decision goes through the manual edit module's own routes. State chips use the atlas matrix's stage colours from `static/vicarius_roles.css` (admin review violet, marked for upload lime, uploaded green, on the edit bench magenta; a stopped start over red), so the review reads in the colours of the matrix beside it.
- **Uploads** (`static/vt_uploads.js`, `templates/voyager_tools/panes_manual_edit.html`): every transect marked for re-upload across the unfinished manual edit projects, each with a tick box; those an upload set holds now, with Watch; those in admin review, read only; and every upload set of the last 7 days with its state and Watch. Upload ticked checks the panel initials, reads the Shelf copy setting, asks for a confirmation naming each transect and what happens to its Shelf copy (renamed to `<folder>_voy1_archive` and kept, or replaced), and starts one upload set through the manual edit module's `POST /manual-edit/api/uploads`. The progress window is the editor's own component (`window.ManualEditUpload.mount` from the manual edit module's `static/manual_edit_upload.js`) in a dialog on the page body, so a relock that hides the panel leaves it open: the upload keeps running on the server, anyone may watch it, and Stop shows only in admin mode. On a host without the manual edit module the pane says so and offers nothing.
- **Timelines** (`static/vt_timelines.js`, `voyagertools/timelines.py`, `voyagertools/manual_edit_views.py`): per manual edit project (created, Finish project pressed, completed, progress, transects by state, the pull while it runs) and per transect (pulled, time in editing, in Metashape with the opens that have no recorded close, in admin review, waiting for upload, uploaded, total, and the upload or checks window running now), newest first, filtered by project, state, editor and creation day, with Copy as CSV and a drawer holding the status history of every atlas row and every note of the transect. The status times come from the registry's status changes (the registry library's `state_intervals`, the time each status lasted, read from `events.csv`) inside the project's window, from its creation to the creation of the next project holding the same transect, and the Metashape time from the transect's open and close events (the manual edit job store's `edit_time`). The total stops at the upload, or when the project is cancelled or fails, or when a later project takes the transect. An upload shows only while its set is queued or running; a set a desktop restart stranded is marked interrupted before the pane reads it, and a set file that cannot be read is named on the row with the reason.

## The eight tools

1. Atlas edit: the processing order table. Transect blocks of rows Voyager 1 has not started, moved up and down or dragged; Save order writes `processing_order.csv` through `registry.set_processing_order`; Lock order in (the confirm names the count and the first and last ids) and Unlock go through `lock_processing_order` and `unlock_processing_order`.
2. Clean workbench: every Voyager 1 processing folder (`{SITE}_{T#}_3D`) under the Workbench roots, matched to its registry rows, compared to the Shelf copy by name and size (`driver.verify.local_snapshot` and `driver.remote.snapshot`), and Delete only when identical: confirmed, anchored inside the Workbench root, one processing_log row per deletion. The walk, the anchor and the delete skip every excluded root, read from the configuration at each call: every stage `driver.space.stage_roots` names except the Workbench (the Edit bench, the Voyager 2 stage, the VIGIL stage), the fallback bench `<workbench_root>/editbench`, the manual edit setting `edit_bench_default`, the bench of every unfinished manual edit project, and nas.yaml `inflight_dir`; when any of them cannot be read, the scan and the delete are refused. The Voyager 2 stage (`voyagertools/clean_voyager2_stage.py`) is listed apart: a working copy goes once every timepoint it served reads step 2 complete with a verified Shelf output location and the Shelf processing location and no turn reserves the transect; an output folder goes only when it matches its Shelf copy; a test run's copy (`test_<stamp>/`) is never offered.
3. Clean manual edit run: every unfinished manual edit project with its rows, history and log tail, each with its own Cancel and prune. The cancel is the manual edit module's one cancel (`manualedit.transfers.cancel_job` with the prune), the same the walkthrough's Cancel project runs, so the page shows its refusal before the button is pressed: the pull still copying, a project leg or a Metashape on a transect, a transect marked, uploading or starting over, a row the atlas reads marked or at a value VICARIUS does not know (repaired from the atlas in admin mode first), or a current-round explanation from Mark done. A cancel marks the project cancelled, returns each row still at `editing` to `awaiting` with its Shelf location, and removes through the manual edit bench removal only the folders nobody opened in Metashape or saved after the verified pull; the page lists what it removes and why it keeps the rest. It runs only in the VICARIUS desktop, which mounts the manual edit module; a standalone panel refuses.
4. Rewind: pick a row and a target (before step 1, before step 0, or before Voyager 2); Dry run lists the moves, the chunk, the registry cells and the status.csv cells; Apply moves the artifacts into `<processing folder>/_rewind/<stamp>/`, removes the chunk through `scripts/rewind_chunk.py` under `metashape -r`, clears status.csv and resets the registry cells with events. The registry resets go through the named reset `rewind` (blank, `awaiting` or `done` to blank). Refused while the row is live, while its manual edit status is `editing`, `review`, `upload` or a value VICARIUS does not know (the stored cell is compared exactly, so `done` with stray spaces around it counts as unknown), while the row sits in an unfinished manual edit project, or while its folder is on the NAS (the driver's pull-back command is shown). Before Voyager 2 (`voyagertools/rewind_voyager2.py`, `docs/adr/0003-voyager2-rewind-renames-the-shelf-output-folder.md`) acts on the whole transect: the Shelf output folder (a real turn's, or a test run's recorded in the voyager2 fact `output_shelf`) is renamed to `<name>_voy2_archive_<YYYYMMDD-HHMMSS>` through the driver's `phase2.archive_output` (nothing on the Shelf is deleted), then every row that carries a Voyager 2 result loses its step 2 cells and output location cells, its console log points into the renamed folder, its voyager2 facts are blanked and its notes cell gets one line, each write with an event; one processing_log row records the rename. It is refused while a run holds the lock, while a Voyager 2 turn reserves the transect, while step 2 runs, while the output is still on this machine, and without the explicit confirmation when a VIGIL fact names one of the timepoints.
5. Spot redo: for Voyager 1, a rewind before step 1 plus the voyager1 fact `spot_redo`, so the Voyager 1 setup window offers the timepoint again; for Voyager 2, the voyager2 fact `redo_requested` on every complete row of the transect, which the registry's readiness rule reads as newer than step 2's finish, so the Voyager 2 setup window offers the transect again and sends its turn with `--force` (the registry's `voyager2_redo_pending`), so every product is rebuilt; nothing moves until that run.
6. Prompts doc: `/mnt/rip/vicarius_drive/docs/agents/voyager-ingest-prompts.md` rendered from Markdown.
7. Parameter defaults: every version, branch and custom set of a phase in voyagerparams with the default marked, the full editor from the schema, the YAML box, Validate, Save as branch, and Save as default behind a dialog that states the significance. Every save writes one settings history line (the key `<phase>/DEFAULT` or `<phase>/branches/<slug>`, the old and new version) through `deps.record_setting`, which the desktop wires to `settings_stores.record_params_save`, then commits and pushes through `paramsstore.commit_and_push`. When the line cannot be written, `ParamsStore.discard_pending` removes the new files and restores `DEFAULT`, and nothing is committed; the standalone host keeps no settings history, so it refuses parameter saves.
8. Camera model: a table editor over `seasons.csv` (camera model, preprocessing, notes per season) through `registry.set_season`.

## Admin mode

Every route in this module checks two gates in order: the module lock (`voyager_tools`; 423 while locked, the exact page "Under development. Please come back later. Email Lauren for questions." with a mailto to lauren.olinger@uvi.edu), then the desktop's admin session (401 `{"error": "locked", "need_unlock": true}` outside it; the cookie is `vicarius_session`, unlocked the same way as every other admin surface). Nobody, including the module owner, reaches a tool without both. On the desktop the page opens two ways, both behind admin mode: the DEV folder item ATLAS CONTROL PANEL (carries `admin: true` in `desktop_boot.js`, so `desktop_icons.js` hides it, and any folder window holding it, until `VICPREFS.admin` is set, and rebuilds the grid the moment admin mode is unlocked or locked again), and the link in the atlas row-view toolbar (also hidden outside admin mode). The standalone host on port 5098 (`standalone_app.py`) gates on its own PIN (`VOYAGER_TOOLS_ADMIN_PIN`) instead of the desktop session, for smoke tests; the platform never starts it.

## The versioning rule (tool 7)

Every version, branch and custom parameter set for a phase (`voyager1` or `voyager2`) lives in the `voyagerparams` checkout (`/mnt/rip/vicarius_drive/vicarius/modules/voyagerparams/github_repo/`), read and written through `voyagertools/paramsstore.py`. Three ways a save reaches it, each with its own rule:

- **Save as default** (behind a dialog that states the significance, since it changes what every future run picks up by default) bumps the phase's version number: MINOR (`v1.2.0` to `v1.3.0`) when only values changed, MAJOR (`v1.2.0` to `v2.0.0`) when a key was added, removed or renamed. Saving a set identical to the current default is refused; there is nothing to version.
- **Save as branch** (name, description, why) starts at the base version's number under the branch's own name (`branches/<slug>/v1.2.0`), so a branch never collides with the default line; a later save to the same branch bumps within that branch.
- **Custom run sets** are written automatically at RUN time by the Voyager 1 and Voyager 2 setup windows, never by this tool: `custom/<run_id>.yaml`, and a custom set never becomes the default by itself.

Every save commits and, when the checkout has a remote, pushes to `laurenkolinger/voyagerparams` (public) through `paramsstore.commit_and_push`; a push failure is reported rather than raised, so a save is never lost to a flaky connection. The full parameter editor is generated from `voyagertools/params_schema_voyager1.yaml` and `voyagertools/params_schema_voyager2.yaml` (label, tooltip, type, default, and range or choices per key; `processing.max_chunks_per_psx` is marked hidden because the project structure controls it, not the operator), so a schema change is the only place a new key's tooltip needs to be written. The Voyager 2 schema holds exactly the keys module 3D_phase2 reads (its `config/voyager2_defaults.yaml`; a test keeps the two equal). The editor shows only the keys the loaded file holds, so a save never invents a value: the legacy voyagerparams `voyager2` v0.1.0 draft holds none of them and is edited through the YAML box.

## Layout

- `voyagertools/views.py`: the blueprint `voyager_tools_bp` (page `/voyager-tools`, fragment `/voyager-tools/fragment`, JSON under `/voyager-tools/api/`), the two gates, and `deps`, one object of plain callables (registry, job store, parameter store, snapshots, rmtree, processing log, chunk runner, the stage layout of the Workbench walk, the Shelf rename, site names, prompts doc) that tests replace with fakes.
- `voyagertools/manual_edit_views.py`, `voyagertools/timelines.py` and `voyagertools/review_queue.py`: the Timelines and Review queue routes and the review fragment on the same blueprint, and the figures behind them; the only write is the manual edit module's own recovery of stranded upload sets and start overs.
- `voyagertools/order_tool.py`, `clean_workbench.py`, `clean_voyager2_stage.py`, `clean_manual_edit.py`, `rewind.py`, `rewind_voyager2.py`, `camera_tool.py`: the tool logic, pure where it can be, with the registry library, `manualedit.jobstore` and `paramsstore` doing every write.
- `scripts/rewind_chunk.py`: the Metashape script (`metashape -r scripts/rewind_chunk.py <psx> --label <id> --out <json>`; `--fake` for tests).
- `templates/voyager_tools/panel.html` (the fragment, root `<section class="voyager-tools">`, including `panes_manual_edit.html` and `panes_settings.html`) and `index.html` (the standalone page); `static/voyager_tools.css` (scoped under `.voyager-tools`); `static/voyager_tools.js` (an IIFE extending `window.VoyagerTools` with `mount(el, opts)`, `mountPanel(el, {onClose, pane})` for the atlas, and `registerPane(key, init)`, the seam every later pane script uses); `static/vt_settings.js` (the settings, desktop and history panes); `static/vt_uploads.js` and `static/vt_timelines.js` (the Uploads and Timelines panes); `static/vt_review.js` (the Review queue pane and `VoyagerTools.mountReview`) with `templates/voyager_tools/review.html` (the review fragment, root `<section class="voyager-tools vt-review">`).
- `standalone_app.py`: a smoke-test host on port 5098 (`VOYAGER_TOOLS_ADMIN_PIN=... python3 standalone_app.py --port 5098`); the platform never starts it.
- `voyagertools/paramsstore.py`, `params_schema_voyager1.yaml` and `params_schema_voyager2.yaml`: the voyagerparams reader and writer and the two editor schemas (plan task A7; program D milestone D1f for Voyager 2).

## API in one table

| Route | Body | Answer |
|---|---|---|
| GET /voyager-tools/fragment?tool=panel | | the panel for the atlas's Control panel tab (mount `VoyagerTools.mountPanel`); no tool is the desktop window; another tool is a 400 |
| GET /voyager-tools/fragment?tool=review&job=&psx= | | one transect's review content (mount `VoyagerTools.mountReview`, opts `{jobId, psx}`) for the atlas's review sidecar and the Review queue; 400 malformed, 404 unknown project or transect, 500 a job file that cannot be read, 503 without the manual edit module |
| GET /voyager-tools/api/review/queue | | `{items, stopped_restarts, marked_for_upload, unmatched, read_at}`; first marks every start over a desktop restart stranded as stopped (the manual edit module's recovery, only where that module is mounted); 500 naming the project when a job file cannot be read |
| GET /voyager-tools/api/state | | order lock, unfinished manual edit projects, default versions, Workbench roots |
| GET /voyager-tools/api/timelines?job=&state=&editor=&since= | | summary, projects and transect rows newest first (the filters narrow the rows only); 400 for a filter that does not parse, 503 `not_mounted` without the manual edit module |
| GET /voyager-tools/api/timelines/detail?job=&psx= | | the registry status spells of every readable id of the transect and its notes, inside the project's window; 400 malformed, 404 unknown project or transect |
| GET, POST /voyager-tools/api/order | {transects: [SITE_T#...], initials} | the order table; saved ids, count, first, last (409 when locked) |
| POST /voyager-tools/api/order/lock, /unlock | {initials, confirm} | lock stamp, count, first, last |
| GET /voyager-tools/api/workbench; POST .../workbench/delete | {path, initials, confirm} | folder plans, the excluded roots and the Voyager 2 stage plans; deleted path, bytes, log row (409 when not deletable, 400 inside an excluded root, 500 when the exclusions cannot be read) |
| GET /voyager-tools/api/manual-edit; POST .../manual-edit/cancel | {job_id, initials, confirm} | {jobs: [summary]}; restored rows with `status_kept`, pruned and kept paths (400 without `job_id`; 409 in flight, certified, or not an unfinished project) |
| GET /voyager-tools/api/rewind/rows; POST .../rewind/plan, .../rewind/apply | {readable_id, target, initials, confirm, confirm_vigil} | rows and targets (`before_step1`, `before_step0`, `before_step2`); the plan; the manifest (409 with the pull-back command when a Voyager 1 folder is on the NAS; 409 for a Voyager 2 refusal; 500 when nas.yaml names no Shelf root) |
| POST /voyager-tools/api/spot-redo/plan, .../spot-redo | {readable_id, phase, initials, confirm} | the plan; the manifest (`phase` is `voyager1`, the default, or `voyager2`) |
| GET /voyager-tools/api/prompts | | the document as HTML |
| GET /voyager-tools/api/params?phase=, .../params/load?ref=; POST .../params/validate, .../params/branch, .../params/default | {phase, values, yaml_text, slug, description, why, initials, confirm} | entries, schema, values; problems and diff; the saved file and the git result |
| GET, POST /voyager-tools/api/seasons | {season_key, camera_model, preprocessing, notes, initials} | the season table; the saved line |

Every write needs `initials` (two to four letters, the registry's rule) and every destructive one `confirm: true`, which the page sends after its dialog. A refusal is one sentence under `error` with status 400, 404 or 409.
